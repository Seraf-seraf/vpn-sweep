# Android: проверка интеграции

Android-клиент содержит встроенный Xray, системный `VpnService`, TUN и защиту
сокетов. Загрузка подписки, подбор и сохранение результата через интерфейс пока
не подключены к runtime; приложение может использовать ранее сохранённый конфиг.
Этот APK не является готовым клиентом.

## Сборка

Нужны Go 1.27.3, JDK 17 и Android SDK с пакетами:

- `platform-tools`
- `platforms;android-36`
- `build-tools;36.0.0`
- `ndk;28.2.13676358`

Из корня репозитория:

```sh
export JAVA_HOME=/path/to/jdk17
export ANDROID_HOME=/path/to/android-sdk
export PATH="$JAVA_HOME/bin:/path/to/go/bin:$PATH"
make android-apk
make android-check
```

Gradle Wrapper проверяет SHA-256 Gradle 8.13. Версии Xray и gomobile закреплены
в `core/go.mod`/`core/go.sum`, Android-зависимости — в Gradle lockfile.
`make android-apk` собирает AAR, затем debug APK для arm64-v8a:
`app/build/outputs/apk/debug/app-debug.apk`. Debug-подпись предназначена для
проверки на телефоне; её ключ хранится вне репозитория стандартными средствами Android.
Не добавляйте реальные конфиги или ссылки подписок в исходники и APK.

Существующий CLI проверяется отдельно командой `make check`. С Go 1.27
запускайте её с `umask 077`: код проекта требует приватные каталоги `0700`,
а `testing.T.TempDir()` в этой версии создаёт подкаталог с учётом umask.

## UI-тесты на устройстве

Для UI-тестов нужен подключённый к ADB Android 14+ (arm64-v8a) или совместимый
эмулятор. Из корня репозитория выполните `make android-ui-check`: цель сначала
собирает Android-ядро, затем запускает `:app:connectedQaAndroidTest` на устройстве.
Тесты используют синтетические UI-данные и не запускают VPN или сетевую проверку.

`make android-check` выполняет lint, локальные unit-тесты и сборку debug APK,
но не запускает device UI-тесты. `:app:assembleQaAndroidTest` только собирает
тестовый APK; она не заменяет `:app:connectedQaAndroidTest`.

## Ранее выполнявшаяся проверка на телефоне

В текущем интерфейсе выбор `working.json` и запуск диагностики недоступны.
Ниже сохранён сценарий прежней интеграционной сборки; выполнить его из текущего UI нельзя.

1. Установить APK на Android 14–16 (arm64), отключить другой активный VPN.
2. Нажать «Выбрать working.json» и выбрать существующий результат vpn-sweep.
   Импорт необходим только для проверки интеграции первого этапа.
3. Нажать «Подключить», разрешить уведомления по желанию и подтвердить
   системный запрос VPN. Статус «Туннель запущен» означает запуск ядра,
   а доступность сервера требует отдельной проверки.
4. Нажать «Проверить TCP, UDP и DNS»: сохранить результаты и счётчики данных
   TUN → Xray и Xray → TUN. Сначала проверяется TLS по числовым адресам
   IPv4/IPv6 без обращения к DNS, затем DNS по TCP, UDP/DNS, системный DNS
   и TLS Google. Ошибка показывает фазу и безопасную причину без адреса сервера.
   Диагностика привязана к системной VPN-сети;
   это отдельное подтверждение интеграции, не изменение политики подбора.
   Затем открыть Google и YouTube в браузере. Вернуться в приложение, проверить
   ненулевое число защищённых сокетов и отсутствие ошибок защиты.
   Повторить после сворачивания приложения и блокировки экрана.
5. Отключить VPN кнопкой приложения и действием уведомления; проверить,
   что системный значок VPN исчезает и повторное подключение работает.
6. Отозвать VPN-разрешение в системных настройках, проверить остановку.
   При потере выбранной сети проверочная версия завершает туннель;
   автоматическое переподключение предусмотрено на этапе 4.

Передать модель телефона, версию Android, тип сети, результат каждого действия
и текст ошибки, если она возникла. Ссылки подписок и содержимое конфигурации
передавать в журнале проверки не нужно. Показанный SHA-256 относится только
к массиву применённых outbounds и помогает сравнить результат без раскрытия параметров.

Открытие страниц подтверждает только проверенный TCP/DNS-путь. Для UDP и IPv6
нужны успешные соответствующие результаты диагностики на телефоне; если DNS
не вернул IPv6 Google, проверка Google отмечается как невыполненная, но контроль
TLS/IPv6 по числовому адресу выполняется независимо. Контрольные адреса TLS —
1.1.1.1 и 2606:4700:4700::1111, имя сертификата one.one.one.one. Это только
диагностика интеграции; проверки подбора Google/YouTube не меняются. Сборка, иконка VPN
и локальные тесты адаптера передачу на телефоне не доказывают.

## Граница конфигурации

Проверочная версия принимает envelope результата экспортёра vpn-sweep:
`log`, `inbounds`, `outbounds`, `routing` и основной outbound с тегом `candidate`.
Все outbounds сохраняются, включая вспомогательный `endpoint-fragment`.
Android заменяет вход на TUN, направляет его трафик в `candidate` и отключает
технические журналы. MTU — 1500 байт; системные маршруты — IPv4 и IPv6 по умолчанию.
DNS приложений направляется на 1.1.1.1 через TUN и найденный outbound.
Имена VPN-сервера разрешаются через защищённые сокеты на DNS физической сети.

Xray `ac5d8a83ba798c390cd89f235c3d4c35c77c1586` встроен без изменения его исходников.
При отказе `protect` адаптер делает сокет непригодным для передачи, поскольку
эта версия Xray не прекращает dial при ошибке контроллера.
Уведомления о лицензиях зависимостей включаются в assets APK при сборке AAR.
Исходники закреплённого Xray доступны в
[upstream](https://github.com/XTLS/Xray-core/tree/ac5d8a83ba798c390cd89f235c3d4c35c77c1586).
